# TG Collector

Веб-застосунок для завантаження **сирих** постів публічних Telegram-каналів у папки на диску.
Працює через веб-версію `t.me/s/<канал>`: акаунт, телефон і API-ключі не потрібні.
Не залежить від коду ДЗ1, тож папку можна скопіювати окремо.

## Запуск

```bash
cd tools/tg-collector
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt        # Windows: .venv\Scripts\pip install -r requirements.txt
.venv/bin/python app.py                          # http://127.0.0.1:8770
```

`--host 0.0.0.0` відкриває застосунок для інших пристроїв у мережі (наприклад, з телефона в тій самій Wi-Fi). Входу немає, тому вмикайте лише в довіреній мережі.

## Як користуватися

1. **Додати канали:** вставте посилання (`https://t.me/name`, `t.me/s/name/123`, `@name` або `name`), по одному в рядку, і вкажіть папку. Застосунок одразу перевіряє канал: назву, кількість підписників, дати першого й останнього поста.
2. **Канали:** список згруповано за папками. Чекбокс біля папки вибирає всі її канали. Щоб перенести канал, змініть назву папки в його рядку.
3. **Період:** подвійний повзунок від найстарішого поста вибраних каналів до сьогодні, точні дати або кнопки 7 днів / 30 днів / 3 місяці / Рік / Уся історія.
4. **Завантажити:** видно прогрес і журнал кожного запиту. «Зупинити» зберігає вже завантажене.

5. **Вкладка «Перегляд»** (угорі праворуч або кнопка «Пости» в рядку каналу) — лише читання, тексти без змін:
   - вибір каналу й пошук у тексті з підсвіткою;
   - фільтри за датами, «лише з фото», «лише без тексту»; порядок «спершу нові» або «спершу старі»;
   - по 50 постів на сторінку, з фото, переглядами, пересиланнями, прев'ю посилань і посиланням на оригінал у Telegram.

   Редагувати й видаляти пости в інтерфейсі навмисно не можна: це сирі дані, і будь-яка правка вплинула б на результати аналізу.

Запрошення в папки Telegram (`t.me/addlist/…`) і приватні чати веб-версія не відкриває. Такі канали треба додавати по одному.

## Сторона каналу

У кожного каналу є поле **сторона** (`side`):

| Значення | У списку | Що означає далі в пайплайні (`hw1-extraction/src/privacy.py`) |
|---|---|---|
| `hostile` | 🔴 ворожий | канал допомагає армії РФ: акаунти, гаманці, реквізити, імена, підрозділи, напрямки й місця передачі техніки **витягуємо й показуємо** |
| `friendly` | 🟢 дружній | українські волонтери: усе перелічене **деперсоналізуємо** (маски `[PERSON]`, `[UNIT]`, `[DIRECTION]`, `[LOCATION]`, `[CARD]`…); фонди й проєкти лишаються |
| `unknown` | ⚪ не визначено | обробляється як дружній, доки сторону не задано |

**Де задається:**
- при додаванні каналу (поле «Сторона»);
- у рядку каналу (випадаючий список біля папки).

Сторона зберігається в `config.json` і дублюється в `channel.json` папки каналу. Тому вона «їде» разом з даними, коли папку копіюють у ДЗ. Сторона — властивість каналу, а не поста: усі пости каналу мають ту саму сторону.

**Канали зараз:**

| Папка | Сторона | Канали |
|---|---|---|
| `volunteers` | 🔴 ворожі | `signalman_diary`, `military_engineer`, `ghost_of_novorossia`, `reihatori`, `surf_noise1`, `makers2fron`, `vrachivyneodni_channel`, `interbrigady2022`, `ekipadobrovolec` |
| `ua_volunteers` | 🟢 дружні | `ssternenko`, `serhiyprytula`, `prytulafoundation`, `victorydrones`, `armyofdrones` |

**Перевіряйте канали перед додаванням.** Популярні імена бувають зайняті підробками: `@wildhornets` і `@dzygaspaw` існують, але це канали з 6 підписниками й одним постом, а не справжні Wild Hornets і «Дзига». Колонка «Історія каналу» (дата першого поста, кількість постів) і кількість підписників допомагають це помітити.

## Що лежить на диску

```
output/                      # змінюється в розділі «Куди зберігати»
  <папка>/
    <канал>/
      posts.jsonl            # один пост на рядок, відсортовано за id
      channel.json           # опис каналу, сторона (side) + історія завантажень (коли, який період, скільки)
      media/<id>_<n>.jpg     # фото, якщо ввімкнено «завантажувати фото»
```

Поля поста: `id`, `url`, `date` (UTC), `text`, `views`, `forwarded_from`, `has_photo`, `has_video`, `photo_urls`, `photos` (локальні файли), `links`, `link_preview`, `document`, `fetched_at`.

Повторне завантаження **доливає** нові пости в той самий `posts.jsonl` і оновлює вже наявні (перегляди, правки). Дублів не буде.

## Важливо

- `output/` **не в git**: сирі тексти містять телефони, картки й гаманці. Маскувати персональні дані (PII) — це вже робота проєкту, який ці дані використовує.
- Швидкість: ~20 постів на запит, пауза за замовчуванням 1 с. Канал на 40 тис. постів повністю завантажується ~35 хв. Для таких каналів краще брати період.
- Кінець періоду в минулому знаходиться бінарним пошуком по id (~10 запитів), тому старі періоди не потребують гортання від сьогодні.
- `config.json`: список каналів і папка виводу. Його можна комітити.
