# HW1: витягування структурованих даних із текстів

Перший кейс курсу AI Engineering: сервіс, який перетворює «брудні» тексти на валідний JSON за схемою та порівнює провайдерську й локальну моделі.

Зараз у репозиторії готовий **збір даних**: скрипт вивантажує пости публічного Telegram-каналу [«Дневник связиста Кибы»](https://t.me/s/signalman_diary) (`signalman_diary`). Це російськомовні пости про зв'язок, обладнання, дрони, збої мереж, а також анонси й рекламу. Тексти різної довжини, з опечатками та змішаною лексикою, тобто такі «брудні», як вимагає завдання.

## Встановлення

Потрібен Python 3.11+.

```bash
pip install -r requirements.txt
```

## Робота на іншому комп'ютері (ноутбук)

Репозиторій приватний, тож для клонування потрібен вхід у GitHub. Найпростіше це зробити через GitHub CLI.

```bash
gh auth login --hostname github.com --git-protocol https --web
gh repo clone distribtech/ai-engineering
cd ai-engineering/hw1-extraction
python -m venv .venv
.venv\Scripts\activate          # Windows; на Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python app/server.py            # http://127.0.0.1:8765
```

**Що буде одразу, а що треба доставити**
- **Пости каналів** є в git у вигляді `data/<канал>_clean.jsonl`. Сирих файлів `data/raw/` у git немає, і сервер тоді читає clean-версії. Кнопка «Оновити» докачує нові пости від найновішого збереженого.
- **Golden set, прогони (`results/runs.jsonl`), промпти** є в git.
- **Ollama з моделлю треба поставити окремо:** https://ollama.com/download, потім `ollama pull qwen3:8b` (5,2 GB). Їй потрібна відеокарта з ~6 GB пам'яті. Без неї модель працюватиме на процесорі в рази повільніше: тоді візьміть меншу, наприклад `qwen3:4b`, і пропишіть її в `.env`.
- **Адреса Ollama** береться з `OLLAMA_URL`, потім з `OLLAMA_HOST`, інакше `http://127.0.0.1:11434` (стандартний порт). Щоб змінити модель чи адресу, скопіюйте `.env.example` у `.env`.

**Як не загубити зміни між комп'ютерами**
- Перед роботою: `git pull`. Після: `git add`, `git commit`, `git push`.
- **Оновлюйте канали («Оновити») на одному комп'ютері.** Clean-файли великі, і якщо оновити їх на обох машинах, `git pull` дасть конфлікт, який вручну не розібрати. Якщо конфлікт таки стався: `git checkout --theirs data/*_clean.jsonl` і знову «Оновити».

## Окремий інструмент збору: TG Collector (`tools/tg-collector/`)

Окремий веб-застосунок у корені репозиторію. Він лише завантажує **сирі** пости публічних каналів і не залежить від коду ДЗ1, тож його можна передати окремо.

- Канали додаються посиланнями (`https://t.me/name`, `@name`) і групуються за папками.
- Період вибирається подвійним повзунком, датами або кнопками «7 днів / 30 днів / 3 місяці / Рік / Уся історія». Кінець періоду в минулому знаходиться бінарним пошуком по id.
- Результат: `output/<папка>/<канал>/posts.jsonl`, `channel.json`, `media/` (фото — за бажанням). Повторне завантаження доливає нові пости без дублів.

```bash
cd tools/tg-collector
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python app.py          # http://127.0.0.1:8770
```

**Як перенести зібране в ДЗ.** Формат `posts.jsonl` той самий, що в `data/raw/`, плюс поля `photo_urls` і `photos`. TG Collector **не маскує персональні дані**, тому clean-версію робимо тут:

```bash
cp ../tools/tg-collector/output/<папка>/<канал>/posts.jsonl data/raw/<канал>.jsonl
python scripts/scrape_telegram.py <канал> --clean-only     # → data/<канал>_clean.jsonl з масками
```

Увага: `cp` **замінює** наявний `data/raw/<канал>.jsonl` і `data/<канал>_clean.jsonl`. Якщо в TG Collector завантажено менший період, старіші пости з ДЗ зникнуть.

`output/` і `data/raw/` у git не потрапляють. Детально — [`tools/tg-collector/README.md`](../tools/tg-collector/README.md).

## Збір даних: `scripts/scrape_telegram.py`

### Як це працює

1. У кожного **публічного каналу** Telegram є веб-версія `https://t.me/s/<channel>`, яка відкривається без входу. Тому скрипту **не потрібні акаунт, номер телефону чи API-ключі**.
2. Одна сторінка показує ~20 останніх постів. Скрипт гортає назад у часі через параметр `?before=<id найстарішого поста>` і зупиняється, коли нових постів більше немає.
3. HTML розбирається через BeautifulSoup. З кожного поста береться власний текст (без цитати, на яку відповідає пост), дата, перегляди, джерело репосту та наявність медіа.
4. Мережеві помилки повторюються до 3 разів. На `429 Too Many Requests` скрипт чекає стільки, скільки просить сервер. Між запитами витримується пауза (за замовчуванням 1 с).
5. Результат зберігається у два файли: сирий і очищений від персональних даних.

### Запуск

```bash
# увесь канал (кілька хвилин)
python scripts/scrape_telegram.py signalman_diary

# швидка перевірка: лише 3 сторінки (~60 постів)
python scripts/scrape_telegram.py signalman_diary --max-pages 3

# лише пости з текстом від 200 символів у clean-файлі, пауза 2 с
python scripts/scrape_telegram.py signalman_diary --min-chars 200 --delay 2
```

Підходить для будь-якого іншого публічного каналу: замініть `signalman_diary` на його username без `@`. Групи-чати й приватні канали веб-версії не мають, тож для них скрипт не працює.

| Параметр | За замовчуванням | Що робить |
|---|---|---|
| `channel` | — | username каналу без `@` |
| `--max-pages N` | усі | обмежує кількість сторінок (по ~20 постів) |
| `--delay S` | `1.0` | пауза між запитами, с |
| `--min-chars N` | `1` | у clean-файл потрапляють лише пости з текстом довжиною ≥ N |
| `--clean-only` | вимкнено | не завантажувати, а переочистити наявний `data/raw/<channel>.jsonl` |

### Вихідні файли

| Файл | Вміст | У git? |
|---|---|---|
| `data/raw/<channel>.jsonl` | усі пости як є, включно з постами без тексту | ❌ ні (`.gitignore`) |
| `data/<channel>_clean.jsonl` | пости з текстом, персональні дані замінено мітками | ✅ так |

Формат: один JSON-об'єкт на рядок (JSONL), пости відсортовані від старих до нових.

```json
{
  "id": 4451,
  "url": "https://t.me/signalman_diary/4451",
  "date": "2026-10-18T12:17:35+00:00",
  "text": "Особо рассказывать пока нечего. ...",
  "views": "1.97K",
  "forwarded_from": null,
  "has_photo": false,
  "has_video": false,
  "has_document": false
}
```

| Поле | Опис |
|---|---|
| `id` | номер поста в каналі |
| `url` | посилання на пост |
| `date` | дата публікації (ISO 8601, UTC) |
| `text` | текст поста; порожній рядок, якщо пост лише з медіа |
| `views` | перегляди так, як їх показує Telegram (`1.97K`) |
| `forwarded_from` | назва джерела, якщо це репост, інакше `null` |
| `has_photo` / `has_video` / `has_document` | чи є в пості фото, відео, файл |
| `links` | посилання з тексту поста (`http(s)://...`); пошук за хештегами `?q=#тег` не зберігається |
| `link_preview` | превʼю посилання під постом: `url`, `site`, `title`, `description`, або `null` |
| `document` | прикріплений файл: `title` і `size`, або `null`. Веб-версія **не дає посилання на завантаження**, лише назву й розмір |

У clean-файлі з `links` і `link_preview` прибрано посилання на Telegram (там можуть бути особисті акаунти) і на платіжні сервіси.

### Очищення персональних даних

Завдання вимагає тексти без персональних даних, тому в clean-файлі регулярні вирази замінюють:

| Що | Мітка |
|---|---|
| посилання `t.me/...`, `telegram.me/...` | `[TG_LINK]` |
| посилання на платіжні сервіси (ЮMoney, Т-Банк, DonatePay, Sponsr, СБП тощо) | `[PAY_LINK]` |
| email | `[EMAIL]` |
| криптогаманець (Ethereum, Bitcoin, TRON, Monero) | `[WALLET]` |
| `@username` | `[USER]` |
| номер картки (16 цифр) | `[CARD]` |
| номер телефону | `[PHONE]` |

Обмеження регулярних виразів:
- **Імена людей лишаються.** Найчастіше вони трапляються в дописах про збір коштів поруч із реквізитами. Такі дописи краще не брати в golden set.
- **Бувають хибні спрацювання.** Довгі числа на кшталт номерів ГОСТ чи діапазонів частот іноді стають `[PHONE]`. На вилучення це майже не впливає, але знати про це варто.

Перед тим як брати пости в golden set, перегляньте їх очима.

Якщо ви змінили правила очищення, перезбирати канал не треба:

```bash
python scripts/scrape_telegram.py signalman_diary --clean-only
```

## Веб-інтерфейс: завантаження, вижимка, перегляд (`app/`)

Два етапи на одній сторінці: **збір сирих даних** (вкладки «Канали», «Вижимка», «Пости») і **обробка в JSON** (вкладка «JSON», де поруч видно пост і JSON, зроблений з нього).

```bash
pip install -r requirements.txt
python app/server.py            # відкрийте http://127.0.0.1:8765
```

З телефона в тій самій Wi-Fi мережі: `python app/server.py --host 0.0.0.0` і адреса комп'ютера в мережі, наприклад `http://192.168.1.5:8765`. Входу немає, тож цей режим відкриває сторінку всім у вашій мережі.

### Звідки беруться дані
Сервер відкриває публічну веб-версію каналу `https://t.me/s/<канал>` без акаунта й читає пости так, як їх бачить будь-який відвідувач. Біля кожного поста є посилання на оригінал і час завантаження. Журнал оновлення показує кожну відкриту адресу.

### Вкладки
- **Канали.** Список каналів зі статистикою (скільки постів збережено, час найновішого поста, коли оновлювали). Галочка вмикає канал у «Оновити вибрані»; кнопка «Оновити» біля каналу оновлює лише його. Нові канали додаються за username (перевіряється, що в каналу є веб-версія). Видалення зі списку не стирає файли з даними.
- **Вижимка.** За 24 години / 3 / 7 / 30 днів: кількість постів, теми, найпереглядуваніші пости, окремо по кожному каналу. Репости між каналами рахуються один раз. «Лише про техніку» фільтрує за ключовими словами. Кнопка «Переказ від локальної моделі» просить `qwen3:8b` написати по одному рядку на кожен із 12 найпереглядуваніших постів. Номери `[n]` ведуть на оригінали.
- **Пости.** Перегляд і пошук у збережених постах за каналом, періодом і сортуванням.

### Вкладка «JSON»: пост і результат поруч
Етап 2: з сирого поста робиться JSON за схемою `src/schema.py` локальною моделлю (Ollama, за замовчуванням `qwen3:8b`).

- **Джерело постів:** golden set (10 розмічених), робочий набір (30) або свіжі пости про техніку. Кнопка «→ JSON» є й на вкладках «Пости» та «Вижимка».
- **Зліва пост.** Підсвічено фрагменти, які потрапили в JSON (назви техніки, організації, місця), тож видно, з чого взято значення.
- **Справа JSON** і «паспорт» прогону: статус, модель, версія промпту, `temperature` і `top_p`, час, токени, кількість спроб. У блоці «Що саме відправлено моделі» видно системний промпт і параметри.
- **Статуси:** `валідний` — відповідь пройшла перевірку схемою з першої спроби; `виправлено з 2-ї спроби` — перша не пройшла, модель отримала список помилок і виправила; `failed` — не пройшла й друга, показується остання відповідь.
- **Порівняння з еталоном** для постів golden set: по кожному полю, скаляри точно, списки за коефіцієнтом Жаккара по нормалізованих назвах (без регістру, лапок і розділових знаків). Поки `golden.json` має статус `draft`, розбіжність може бути помилкою еталона.
- **Історія:** кожен прогін дописується в `results/runs.jsonl` (модель, версія промпту, параметри, обидві спроби, час). У селекторі «Прогони» видно всі запуски по цьому посту, тож промпти v1 і v2 можна порівнювати на одному тексті.

Логіка вилучення лежить окремо від веб-сервера в `src/extract.py` і не залежить від Flask: її можна викликати зі скрипта для пакетного прогону. Мережеві помилки й таймаути повторюються (до 2 разів), запити до відеокарти йдуть по одному.

Промпти: `prompts/v1.txt` (baseline) і `prompts/v2.txt` (правила нормалізації). Що змінили й чому — у `prompts/CHANGELOG.md`.

### Як працює оновлення
Для каналу зі збереженими постами докачуються лише нові: сервер гортає канал від найновішого поста назад, поки не дійде до вже збереженого `id`. Заодно оновлюються перегляди й правки свіжих постів. Для нового каналу береться вказана кількість днів (за замовчуванням 30). Повторне натискання нічого не дублює. Те саме з командного рядка:

```bash
python scripts/scrape_telegram.py military_engineer --update
```

### Обмеження
- **Переказ від моделі на 8B неточний.** Бувають спотворення («бойовикам» замість військовослужбовцям), суржик, пропущені деталі. Тому до кожного рядка додано посилання на оригінал: перевіряйте. Для кращої якості потрібна сильніша модель.
- **Тема «техніка» — це ключові слова.** Фільтр може пропустити пост або захопити зайве (корінь «связ» ловить і «в связи с»).
- **Пости без тексту** (лише фото чи відео) у вижимці й списку не показуються. Медіа сервер не завантажує.
- **Локальна модель:** адреса з `OLLAMA_URL`, інакше з `OLLAMA_HOST`, інакше `http://127.0.0.1:11434`; модель з `OLLAMA_MODEL` (`qwen3:8b`). Їх можна задати у файлі `.env` (зразок у `.env.example`).

## Статті за посиланнями: `scripts/fetch_articles.py`

Збирає тексти сторінок, на які посилаються пости. Це довші й чистіші тексти, ніж самі пости, тож вони знадобляться на етапі RAG.

```bash
python scripts/fetch_articles.py signalman_diary
python scripts/fetch_articles.py signalman_diary --limit 5   # швидка перевірка
```

**Як працює**
1. Бере `links` і `link_preview.url` з `data/<channel>_clean.jsonl`. Telegram і платіжні сервіси вже прибрані на етапі очищення.
2. Відкидає посилання, де немає тексту статті: відео (Rutube, YouTube, VK, Дзен), файлообмінники (Яндекс.Диск, Google Drive, Mail.ru Cloud), магазини, прямі посилання на файли (`.pdf`, `.zip`, `.apk`…).
3. **Завантажує лише HTML.** `Content-Type` перевіряється до читання відповіді, розмір обмежено 5 MB. Файли скрипт не завантажує.
4. Основний текст витягує [trafilatura](https://trafilatura.readthedocs.io/): без меню, реклами й коментарів. Потім той самий `clean_pii`, що й для постів.
5. Кириличні домени (`%D0%B1…`) переводяться в punycode. DNS-помилки не повторюються.

**Результат:** `data/<channel>_articles.jsonl`, один рядок на URL, включно з невдалими:

| Поле | Опис |
|---|---|
| `url`, `final_url`, `host` | посилання з поста та адреса після редиректів |
| `source_posts` | id постів, де є це посилання |
| `title`, `date` | заголовок і дата статті (якщо trafilatura їх знайшла) |
| `text`, `chars` | текст статті та його довжина |
| `error` | чому не вдалося, або `null` |

| Таймаут | 40 — схоже, теж блокування |
| Інші помилки | 6 (HTTP 4xx/5xx, обірване з'єднання) |

Найбільше статей з telegra.ph (21): спорядження, ретранслятори, антени, польові телефони. Решта — GitHub, документація Motorola/Silvus/Analog Devices, Habr, Google Docs.

**Відомі обмеження**
- **Заблоковані сайти не зібрано,** і скрипт блокування не обходить. Результат залежить від мережі, з якої його запускають.
- **Дублікати:** різні URL можуть вести на ту саму сторінку (наприклад, дві адреси однієї Google-таблиці).
- **Короткі тексти** (< 300 символів, 3 шт.) — це заглушки на кшталт paywall. Для RAG їх варто відфільтрувати за `chars`.
- **Різна тематика:** серед статей є й нетехнічні, зокрема з мовою ворожнечі. Перед використанням у RAG їх варто відфільтрувати.

## Схема: `src/schema.py`

Pydantic-модель `ExtractedPost` описує, що LLM має витягнути з одного поста. JSON Schema для провайдерів генерується з неї:

```bash
python -m src.schema        # -> schema.json
python -m tests.test_schema # перевірка на розмічених прикладах
```

| Поле | Тип | Що містить |
|---|---|---|
| `post_type` | **enum** `PostType` (12 значень) | призначення поста: `delivery_report`, `equipment_review`, `news`, `event`, `announcement`, `advertisement`, `vacancy`, `request`, `guide`, `personal`, `humor`, `other` |
| `language` | **enum** `Language` | `ru` / `uk` / `en` / `mixed` |
| `summary` | `str` ≤ 300 | одне речення українською |
| `equipment` | **список вкладених об'єктів** `EquipmentItem` | конкретна техніка чи ПЗ з тексту |
| `organizations` | `list[str]` | компанії, підрозділи, проєкти, канали, як написано в тексті |
| `locations` | `list[str]` | географія в називному відмінку (`в Мск` → `Москва`) |
| `event_date` | `date \| null` | дата події, тільки якщо вона повна в тексті |
| `money` | **список вкладених об'єктів** `Money` | суми з тексту |
| `call_to_action` | `bool` | чи просить пост щось зробити (написати в бот, податися, зареєструватися, зробити репост) |

**`EquipmentItem`**: `name`, `category` (тип техніки, **enum** з 22 значень, див. нижче), `manufacturer`, `quantity`, `unit`.

**Типи техніки (`category`, v2).** Для аналітики їх згруповано в `CATEGORY_GROUP`. Групи модель не заповнює, вони обчислюються з `category`.

| Група | Категорії |
|---|---|
| `comms` — зв'язок | `radio`, `phone`, `antenna_mast`, `cable`, `satellite`, `network` |
| `drones` — БПЛА | `drone_fpv`, `drone_multirotor` (Mavic, Matrice, важкі мультикоптери), `drone_fixed_wing`, `drone_component` (мотори, відеопередавачі, пульти, окуляри, АКБ) |
| `ew_recon` — РЕБ і розвідка | `ew_sigint` (РЕБ, РЕР, детектори, радари), `optics` (тепловізори, нічні приціли) |
| `support` — забезпечення | `power`, `vehicle`, `it_hardware`, `software`, `tools` |
| `personnel` — особовий склад | `protective_gear` (бронежилети, шоломи), `field_gear` (одяг, спальники, намети), `medical` |
| `weapons` | `weapon_related` (зброя, боєприпаси, скиди, детонатори) |
| `other` | `other` |

Визначення кожної категорії записані в `description` поля, тож модель бачить ті самі межі між типами, що й розмітка.

**Що змінилося з v1:** категорію `drone` розбито на 4 підтипи. Додано `network`, `it_hardware`, `protective_gear`, `field_gear`, `medical`, `weapon_related`. Golden set v1 лишився валідним, бо `drone` у ньому не траплялася.

**`Money`**: `amount_min`, `amount_max` (для діапазону), `currency` (**enum** `RUB`/`USD`/`EUR`/`UAH`/`OTHER`), `purpose` (**enum** `price`/`salary`/`purchase_total`/`fundraising`/`other`).

Вимоги завдання: 9 полів (потрібно ≥ 6), 6 enum-ів (потрібно ≥ 1), вкладені об'єкти в списках (потрібно ≥ 1).

> Аналітична частина з кількома каналами (розділ «OSINT-набір» нижче) — це розширення поза ДЗ1. Для оцінювання ДЗ1 достатньо 30 постів із `dataset.jsonl`.

### Рішення в схемі
- **Усі поля обов'язкові**, без значень за замовчуванням: відсутнє значення — це `null` або `[]`. Разом з `extra="forbid"` (`additionalProperties: false`) це дає схему, сумісну зі strict structured output OpenAI. Схема працює й з Anthropic, Gemini та Ollama (`format=<schema>`).
- **Правила нормалізації записані в `description` полів:** «80к» → 80000, «в Мск» → «Москва», не вгадувати виробника тощо. Description потрапляє в JSON Schema, тож модель бачить ті самі правила, за якими розмічено golden set. Тому description написано англійською.
- **Валідатори:** `quantity > 0`, `amount_max ≥ amount_min`, дата лише ISO `YYYY-MM-DD`. Повтори в `organizations` і `locations` прибираються без урахування регістру.
- **`summary` у точності не враховується**, бо це вільний текст. Поле знадобиться пізніше для RAG.

## Golden set: `data/golden.json`

10 постів, розмічених за схемою. За ними міряється точність моделей по полях. Кожен запис має такі поля:

| Поле | Опис |
|---|---|
| `id`, `url`, `text` | пост, текст збігається з `dataset.jsonl` |
| `status` | `draft` — чернетка, `reviewed` — перевірено людиною |
| `label` | еталонний `ExtractedPost` |
| `review_notes` | спірні рішення, які варто перевірити |

Як перевіряти: прочитайте `text`, виправте `label`, перегляньте `review_notes` і поставте `"status": "reviewed"`. Потім запустіть:

```bash
python -m tests.test_golden   # схема, id, незмінність текстів
```

### Правила розмітки
Вони ж записані в `description` полів схеми, тож модель отримує ті самі правила.
- **`quantity`** — лише якщо число написане явно. «экземпляр» чи «новый генератор» дають `null`.
- **`manufacturer`** — лише якщо його названо, зокрема як частину назви моделі (`TYT-7500` → `TYT`). Країна виробництва (`производства Украины`) виробником не вважається.
- **`equipment`** — лише конкретні вироби. Конкретний предмет, про який пост, рахується й без моделі («убило новый генератор» → `генератор`), а загальні згадки типів техніки («генераторы в больницах», «паяльные станции» в описі умов роботи) — ні.
- **`organizations`** — як у тексті, але в називному відмінку, без емодзі й з виправленими очевидними опечатками (`Призрак Новоросии` → `Призрак Новороссии`), щоб одна організація в різних постах рахувалася як одна. Компанія записується короткою назвою, так само, як у `manufacturer` (`Московский завод осветительных установок Аргус-М` → `Аргус-М`). Платформи, згадані лише як посилання чи хештеги (Telegram, VK, Rutube, Дзен, MAX), не включаються.
- **`locations`** — у називному відмінку й завжди російською, навіть в англомовному пості (`Mariupol` → `Мариуполь`), щоб місця в аналітиці не дублювалися в різних написаннях. Місце виробництва техніки теж записується, навіть якщо воно є лише прикметником чи частиною назви компанії (`производства Украины` → `Украина`, `Московский завод` → `Москва`).
- **`event_date`** — дата події, а не поста. Для діапазону береться перший день. Рік можна взяти з контексту (`Дронница-2026`). Відносні дати («сегодня») дають `null`.
- **`call_to_action`** — `true` також для питань до читачів («Может кто знает решение?») і для посилань на допомогу каналу.
